# 可自定义的 Git 工作空间

## 边界

UI 接收结构化的 `RepositorySnapshot`，不直接构建或解析 Git 命令。`src/services/git.ts` 定义前后端契约；`useRepository` 提供统一的打开仓库、刷新、暂存、提交、切分支等动作。按钮、面板、快捷键通过这些动作调用相同的 Rust 服务。

布局模型只保存面板 ID、顺序与隐藏状态。移动面板交换两个网格槽位；宽度跟随槽位，首行 4/8、下一行 4/5/3，避免换位产生空洞。窄窗口会重新排版。当前版本不提供自由像素定位、拆分停靠和拖动尺寸。

仓库状态由 Rust/Git 提供。选中文件、过滤条件属于界面状态；提交草稿提升到工作空间并按仓库路径隔离；布局和主题只保存到应用本机存储。

## 添加一个面板

1. 在 `src/layout/model.ts` 的 `PANEL_IDS` 添加稳定 ID。
2. 在 `WorkspaceGrid.tsx` 添加标题与图标。
3. 实现独立 React 组件，通过 props 接收数据和动作。
4. 在 `App.tsx` 的 `renderPanel` 中注册组件，并补充布局菜单说明。
5. 若需要新 Git 能力，在 `git.ts` 定义类型化接口，再增加对应 Rust command。不要在面板中拼 shell 命令。

布局读取会过滤未知 ID、移除重复项并补充新增面板，因此扩展面板时无需清除用户现有布局。未来需要变更持久化格式时，应提升布局版本并编写迁移。

## 启动

`index.html` 内嵌轻量 loading，React 和依赖加载前即可显示。应用初始化时检查本机 Git，尝试恢复最近仓库。初始化完成后通过 `onReady` 淡出 loading；850ms 的最短展示时间只用于避免闪烁。React 渲染异常由 ErrorBoundary 提供恢复入口。

未打开真实仓库时，应用使用空快照并显示打开仓库入口，不展示更改、提交、分支面板和统计。启动时仍会尝试恢复最近打开的真实仓库，失败时保留空白起始页并显示错误。浏览器模式不访问本机 Git，不提供模拟数据或模拟写操作。旧存储中的演示仓库记录会被过滤。

## 窗口与系统托盘

`src-tauri/src/tray.rs` 在原生启动阶段创建系统托盘，使用应用图标，右键提供“显示窗口”和“退出 easygit”。左键点击或双击图标恢复并聚焦原有主窗口，最大化状态不主动重置。标题栏最小化按钮调用隐藏窗口；原生关闭（含 Alt+F4）和任务栏最小化同样隐藏到托盘，保留 WebView、当前工作区和未提交草稿。窗口隐藏后已有刷新逻辑暂停自动轮询。

托盘退出通过 `easygit://quit-requested` 通知前端，`windowLifecycle.ts` 先执行 `flushStorage`，成功后调用 `exit_app` 真正退出。重复退出请求合并，保存失败时恢复窗口并提示，允许重试。前端初始化完成、监听注册成功后才将退出桥接标为就绪；启动失败时托盘的退出仍然可用。原生窗口行为可使用 `cargo run --offline --example tray_smoke` 在独立空白窗口和临时 WebView 数据目录中检查。

## 项目文件浏览与编辑

`git/files.rs` 提供 `list_project_files`、`read_project_file` 和 `save_project_file`，通过 `services/project.ts` 暴露类型化接口。目录按层读取，文件名搜索使用有输出上限的 Git 文件列表，不扩充定时刷新的快照。忽略规则通过 NUL 分隔的 `git check-ignore --stdin` 批量核对，该命令需要关闭通用 literal-pathspecs 模式；`.git` 始终隐藏，链接、Windows reparse point 和嵌套仓库不向下遍历。

交互搜索使用独立的 `git/file_search.rs` 与 `search_project_files` / `cancel_project_search` commands，不获取仓库写操作锁。每个文件面板拥有独立 client ID 和递增 generation；新查询、刷新、切换模式或卸载会取消旧任务。后端保留取消标记以拒绝迟到的旧请求，Git 文件清单子进程复用有界输出、超时及 Windows Job 清理，并每轮检查取消标记。分页复用一次清单和扫描游标，不重复读取全项目；会话数及寿命有上限，取消和完成后释放扫描数据。

文件名和内容搜索都使用转义后的 Rust regex 做忽略大小写的字面匹配。内容扫描采用最多 4 个 IO 工作线程、约 40ms 的批次预算，每 16 KiB 读取及逐行匹配检查取消；保留每个文件的路径安全检查，跳过二进制、非 UTF-8 和超过 2 MiB 的文件。每批最多 50 条、每文件最多 20 处、总计最多 1000 条；清单限制为 32 MiB / 50 万项。`useProjectSearch` 使用 300ms 防抖，稀疏结果发布进度并让出界面调度，首轮累计 50 条后暂停，用户按需继续。搜索列表只渲染可见窗口并支持方向键导航。行列及片段高亮偏移均用 UTF-16，点击相同文件的新匹配不会重建编辑器或丢失草稿；编辑器收到独立定位请求后选择并滚动到对应行。

`components/files/useFileEditor.ts` 在 App 层持有独立选中文件、编辑草稿及异步请求版本，隐藏面板不会卸载编辑会话。编辑器和语言包按需加载，CodeMirror 的撤销历史不随 React 重渲染重置。`pendingChanges.ts` 将保存／放弃／取消确认接入项目打开、仓库写操作、移除当前工作区及托盘退出；关闭到托盘仍保留内存中的草稿。未保存内容不自动写入项目文件，也不承诺异常退出后的草稿恢复。

保存与现有 Git 写操作共用仓库锁，依据读取时的 SHA-256 再次核对磁盘内容，以同目录临时文件替换目标并保留文件权限、UTF-8 BOM 和原有换行风格。保存仅写工作区，不改索引；即使写入后的 Git 快照刷新失败，也返回已保存文件版本并单独提示刷新错误。后台重新读取和窗口恢复检查不得覆盖未保存草稿，保存前还会再校验一次。冲突文件由现有冲突解决流程处理。

## Git 服务

作者和仓库信息集中在 `src/services/appInfo.ts`，版本直接读取 package.json。`useAppUpdates` 在 App 层维护检查与下载状态，使关于窗口关闭后仍能继续下载；仅启动检查一次，其余由用户触发。Rust `updates.rs` 请求固定 GitHub Releases API，按系统和架构选取安装包，流式下载并校验大小与可用的 SHA-256 后发布文件；浏览器链接仅允许作者、项目和发布页面。更新网络请求不放宽 WebView CSP。打包及版本同步见 [releasing.md](releasing.md)。

状态使用 `git status --porcelain=v1 -z`，路径通过独立命令参数传递，使用 literal pathspec，不经过 shell 拼接。写操作统一加仓库锁，执行结束后返回新快照。后台任务通过 Tauri async command 调度；Windows 子进程隐藏控制台。

`git/stash.rs` 根据 selector 和不可变 SHA 同时核对记录，避免列表变化后恢复或删除错条。恢复使用 `apply --index` 保留暂存状态，pop 在恢复成功后再次校验记录再删除；冲突保留记录并返回新快照。保存命令不接收文件路径，在该调用中用 `--no-literal-pathspecs` 覆盖通用 literal 模式，使 Git stash 内部正确清理已保存的新文件；否则 Windows Git 2.42 会留下这些文件。

`git/operations.rs` 为 merge、rebase、cherry-pick、revert 提供继续、取消、跳过（merge 除外）。操作标记生成 token，执行前结合快照指纹、HEAD 和分支重新核对；冲突未解决时不能继续。取消和跳过需要确认，编辑器使用非交互模式，保留 Git hooks。失败或进入下一轮冲突同样发布实际快照，避免界面停留在旧状态。

`git/inspect.rs` 解析带 NUL 分隔的变更文件列表并处理重命名。提交详情与分支对比均使用固定提交 SHA，按所选文件读取只读差异，禁用外部 diff/textconv；根提交与合并提交分别对比空树和第一父提交。前端丢弃切换文件或选择后迟到的响应，UTF-8 差异限制为 2 MB。

`git/history.rs` 的按需接口每次返回 25 条及下一页位置，可按提交信息做忽略大小写的字面搜索，或限定完整本地/远程分支引用。分页 key 绑定 HEAD、上游、所选分支及关键词，位置改变时拒绝拼接旧结果。提交归属批量计算，不为每条记录启动 Git。默认后台快照仍只读取 10 条，搜索与翻页独立于工作区轮询。已发布普通提交允许 revert；soft/mixed 继续保护共享历史。

快照中的每个分支包含其提交 SHA，并参与刷新指纹。查看其他分支的历史时，该 SHA 变化会丢弃旧请求并从第一页重新读取；所选分支被删除时提示重新选择，不会退回显示当前分支的历史。

打开仓库（含启动恢复、最近项目切换）先返回本地快照，再对已配置远程的项目自动执行 `fetch --all --prune`。远程获取有独立进行状态，不占用界面的本地操作锁；同次打开期间重复获取共享请求，切换项目或移除项目会隔离旧请求的成功与失败。获取完成后等待本地写操作结束，再重新读取快照，丢弃获取前的旧读取结果；期间若又发生本地写入则重读，避免覆盖新的暂存/提交状态。定时和焦点刷新仍仅读取本地状态；网络失败保留当前内容并提供手动“获取更新”重试，获取过程不执行 pull 或 merge。

分支面板提供“获取更新”和“拉取更新”。拉取要求当前分支已设置上游且有待拉取提交，并显式使用 Git merge 模式；工作区有未提交改动时遵循 Git 的保护规则。成功后返回新快照。发生合并冲突时保留 merge 状态和冲突文件，让现有工作区冲突解决工具继续处理；其他 Git 错误显示给用户并刷新仓库状态。

分支面板标题栏的加号会从当前 HEAD 创建并切换到新的本地分支。名称由 Git 校验；已有分支名、进行中的 Git 操作和未解决冲突会阻止创建，正常未提交修改由 `git switch -c` 保留。

点击远程分支通过 `checkout_branch` 的 `remote` 标记执行跟踪分支切换：优先复用上游匹配的本地分支，否则复用同名且无其他上游的分支，或从远程跟踪引用创建本地分支并设置上游。分支映射与拖拽合并共用 `resolve_remote_branch`，切换不执行快进、pull 或 merge，保留已有分叉和未推送提交；重名且跟踪其他上游时明确报错。未提交更改由 Git switch 的保护规则处理，进行中的 Git 操作与未解决冲突阻止切换。

分支拖拽合并支持本地与远程跟踪分支作为来源和目标，沿用原有预览和确认弹窗。`sourceRemote`、`targetRemote` 贯穿拖拽、预览及执行，后端分别解析完整 `refs/heads/`、`refs/remotes/` 引用，避免同名歧义。`merge_target` 优先复用跟踪目标远程引用的本地分支，否则复用同名且无其他上游的本地分支，或在确认后创建并配置上游；落后时快进同步，领先时保留本地提交，分叉或跟踪其他上游时提示先处理。预览展示实际本地目标及同步动作，并按同步后的目标计算提交列表；执行前核对来源、远程目标、本地目标名称及 SHA，变化时拒绝执行。远程内容以上次获取为准，合并不自动推送。

保留 Git 自身的配置、hooks 与错误信息。冲突差异保持原始 combined 格式展示，避免作为普通单列 unified diff 误解析。差异页的整文件撤回复用工作区的确认与 Git 服务，保留已暂存内容；暂存区提供取消暂存。

普通差异与全屏左右比对将连续增删行识别为独立变更块，行号旁提供撤回入口和单块确认预览。`discard_diff_block` 在仓库锁内重新生成零上下文差异，核对所选块的行号、增删文本和末尾换行标记，只使用 Git 生成的路径与补丁反向应用到工作区，不写入索引。独立补丁按工作区坐标定位，防止前面的其他修改改变行偏移；块已变化时拒绝执行。冲突、二进制内容与工作区重命名不支持普通区块撤回。

统一差异按块延迟远离可视区域的语法高亮并复用解析结果；原始文本和操作按钮仍保留在页面中，以支持浏览器查找、跨屏选中和键盘操作。选中文本时推迟高亮替换，自动换行由浏览器实际布局。超过 10,000 行时默认显示完整原始文本，避免创建大量行节点；用户仍可主动加载完整视图以使用语法高亮和区块撤回。

冲突工具通过 `read_conflict` 读取索引 stage 2/3 与工作区文件，前端只处理文本冲突块及编辑草稿。`resolve_conflict` 在仓库锁内校验读取版本，检查残留冲突标记，写入结果（或检出选定版本/接受删除）并执行 `git add`。读取版本包含索引与工作区内容，外部修改后拒绝覆盖。UTF-8 文本支持 diff3、自定义标记长度和逐块合并；二进制文件支持整文件选边。符号链接、子模块与超过 2 MB 的文件交由外部工具处理。标记解决不自动提交或继续 rebase 等操作。

下一阶段可沿当前接口补充：原生目录选择器、分块/逐行暂存、可调整槽位宽度、push 的进度与取消、worktree 面板、交互式 rebase 编排。

## 项目脚本

项目脚本使用独立面板 ID `scripts`，默认显示并接入已有拖拽、键盘移动、布局持久化和显示/隐藏设置；旧布局自动追加新面板，保留原有顺序。`read_project_scripts` 从当前仓库根目录读取 package.json，优先使用 packageManager 声明，再根据锁文件识别包管理器，缺省使用 npm。仓库刷新或点击面板刷新按钮后重读脚本，不自动运行。

后台定时刷新和窗口焦点刷新共享进行中的仓库读取，同一仓库内重复请求不排队；打开仓库或写操作会使旧请求失效。脚本和差异面板在同一项目/文件刷新期间保留内容、滚动位置和按钮节点；脚本只在首次读取或点击自身刷新按钮时显示加载动画、禁用运行按钮。差异区块操作在后台刷新期间保留入口，由后端核对最新变更块。刷新失败时保留已有结果并在底栏提示，切换项目或文件仍立即隔离旧内容。

自动轮询只在窗口可见且有焦点时运行，读取完成后再安排下一次；持续无变化时按 8、16、30 秒放缓，回到窗口立即检查。后端快照指纹包含 Git 状态及变化文件、索引、脚本输入的元数据；静默读取未变化时保留原快照，避免差异和脚本重复读取。手动刷新仍强制发布快照。提交归属利用拓扑日志一次计算，分支与上游信息合并到现有引用查询，Git 版本在进程内复用。测量与边界见 [performance.md](performance.md)。

`run_project_script` 只接受脚本名和预览时的命令/包管理器，在启动前重新校验，拒绝已删除或变化的脚本。执行 package-manager run 加脚本名，脚本正文不拼入终端启动命令；脚本名限制为字母、数字及常用分隔符。Windows 在项目目录启动独立 PowerShell 控制台（NoExit），macOS 使用 Terminal，Linux 尝试系统终端。终端独立于应用，输出、Ctrl+C 停止与包管理器缺失等错误在终端内处理；应用中的“已打开终端”仅表示终端已启动。
